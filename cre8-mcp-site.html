The workflow the connector documents

Four questions, asked in order

Each stage answers something the model cannot get right by guessing. Skip one and you get markup that builds cleanly and renders wrong.

01

Find it by meaning

Search runs on embeddings of the catalog, so a description of the job finds the component even when they share no words.

search_components("something to warn the user their payment failed")
cre8-inline-alert0.321
cre8-field-note0.307
cre8-alert0.281

Not one of those names contains the words payment, warn or failed. Lexical matching returns nothing here.

02

Ask how it takes content

Every component accepts content through either children or slots, never both — and the split does not follow from the name. This is where most attempts fail.

get_content_model("card")
{ "contentVia": "slots",
  "slots": ["default", "header", "footer"],
  "rule": "Using children on cre8-card
           is a validation error." }
03

Ask what may nest where

Compound children are not optional scaffolding. Cells live in rows, rows in a header or body, and rows hold their cells in slots.default.

get_composition("cre8-table")
cre8-table
├─ cre8-table-header
│  └─ cre8-table-row
│     └─ slots.default
│        └─ cre8-table-header-cell
└─ cre8-table-body
   └─ cre8-table-row
      └─ slots.default
         └─ cre8-table-cell

Returned with a worked subtree that was re-validated against the catalog before you got it.

04

Check it before you ship it

Errors are path-qualified, so the model is told which node broke which rule — not merely that something, somewhere, is invalid.

validate_a2ui_spec({ … })

$.slots.body[0].props.variant: value 'bogus' not in enum ['primary', …]

Undeclared props are rejected, not ignored. If the model invented it, validation says so.

Provenance

It answers from evidence, not from names

The composition graph is built from the library's own source. Every nesting it reports carries the evidence it came from, and where nothing demonstrates a nesting, it says so rather than guessing.

A name is not a containment rule

cre8-tag-list does not tell you which way containment runs. The graph does, because it read the templates. Counts and lists are computed from the shipped catalog, so the connector cannot drift from the library the way hand-written documentation does.

A previous hand-maintained skill drifted until 46% of the components it documented no longer existed. That is the failure this replaces.

Beyond markup

Or skip the markup and stream the interface

When the deliverable is the interface rather than the source, the connector opens a live surface: a URL a person watches while the agent builds into it, with clicks coming back the other way.

The round trip

openreturns a URL · validated on arrival, so an invalid spec opens nothing
streampass the whole tree; the server works out the minimal patch
dataone bound value costs one small message, not a re-render
eventsa click returns as handler + path + detail

$.children[2].slots.footer[0] — the same path grammar you patch with is the one events report back on.

Elements keep their state

Because the server diffs rather than replaces, nodes that did not change keep their focus, scroll position and animations. Text streams token by token into the trailing node without resending the tree.
